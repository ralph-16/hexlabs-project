# 3. Build Log: Major Prompts and Decisions

This log covers the five prompts that changed SIKAD the most. Sources: the prompt files in `prompts/`, `build-prompts_v3.md`, `process-log.md`, past Claude Code sessions, and the git history (9 to 14 Oct 2026).

| Step | What We Asked / Changed | Why We Did It | Result / Next Decision |
|---|---|---|---|
| 1 | **Product definition** (`prompts/prompt-1/prompt.md`, `user_story.md`). We asked for the first working prototype: a vanilla HTML/CSS/JS PWA where a typed brain dump becomes tasks, then a schedule, then a replan. | We needed one clear source for what SIKAD is ("What should I work on next?"), what it is not (not a chatbot, tutor or LMS), and how a real student uses it from first launch to a disrupted day. | A working prototype with a scheduling engine, a brain-dump parser and a local store (commit `ad5a1e4`). Next decision: give it a real visual identity before adding more features. |
| 2 | **Design audit and `design.md`** (`prompts/prompt-2/updated_context.md`, then `prompt-3/integrate.md`). We asked for an audit of the product, brand and design system and a final `design.md`, with no code changes. Then we applied it one screen at a time, with light and dark themes. | The prototype worked but looked generic. Every screen should follow one documented system instead of ad-hoc styling. The exported CSS contained Tailwind/Vite output, so we kept only the tokens. | `design.md` became the source of truth (Forest, Paper, Butter, Sage, Sky, Harbor, Ink tokens; one Butter button per view; lock + "Fixed"; ≈ + "AI estimate"). The app was restyled without touching the engine or the JSON contracts (commits `aab1fc1`, `adc1dd1`). |
| 3 | **Final implementation brief** (`prompts/prompt-5/sikad_final_implementation.md`). We built the whole approved journey as one connected flow: setup, Ask SIKAD, brain dump, schedule, replan, Done/Snooze/Undo. | The journey had been approved. The parts had to share one application state, not exist as separate demo screens, so the core flow really works. | End-to-end flow working (commit `82784e9`). Next decision: get an outside-eye UI/UX audit, because the app worked but still felt like a prototype. |
| 4 | **UI/UX audit v3 and build prompt pack** (`SIKAD-UIUX-AUDIT-REPORT_v3.md`, `build-prompts_v3.md`). The audit gave finding IDs (F01–F30, R01–R07, S02–S05) and 13 batches. `CLAUDE.md` became a strict rulebook: one batch per session, targeted edits, `node --check`, and a process-log entry for each batch. | Tokens were limited and graded. Small, numbered batches with acceptance checks kept each change focused and verifiable. **Key decision:** no DEMO badges in product mode. Simulated data gets one muted caption, and presenter tools live only in the judge dock. | Batches 1–13 built: judge mode, a single Undo, one-tap focus, grouped classes, a limits card, simulated integrations, fluid desktop, past-week snapshots, and realistic BSIT 3B-G1 sample data (17 classes, 31 assignments) that shows a real time shortage. |
| 5 | **Adaptive scheduling: check-ins instead of auto-completion** (the 14 Oct prompts). An auto-complete version was built first and then **reversed**. We approved a narrow exception for engine.js, store.js and parser.js (defects E2, E3, E4, E7, E11 in `errors.md`). Early-finish rescheduling was reviewed against the design principles before any code was written. | **Key decision:** scheduled time is not completed work, and the student always decides. A block that ends becomes a check-in (Done / Partly / Not done). Filling freed time is only a suggestion, while keeping the plan valid still happens automatically. Risk is shown as a status plus a reason, not a percentage. | Recommended schedules now compare whole plans, overdue work goes in today's first opening, and "Use the time you freed?" asks before moving anything. A regression (E22) was caught and fixed. 131 logic tests passing, plus a 2,400-step random-action run with no errors (commits `6df1132`, `7d7eb3f`, `84aa611`). |
